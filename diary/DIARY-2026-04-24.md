## 2026-04-24

- 今天是 v3 从“高速推进中的东京版”正式收成 release candidate 的一天。前一天我们已经把 MapLibre、玩法壳、多人入口、replay、through-running regression 和 Tutorial/Advanced 入口基本跑通；今天的核心任务是把这些成果从“看起来能玩”推进到“数据和 planner 语义足够可信，可以冻结一个基线”。
- 一开始先补齐控制文件和顶层说明，把 `README.md`、`ROADMAP.md`、`STATUS.md` 和最近的 memory 重新对齐到真实现状：当前公开主线是 `v2` 全国新干线和 `v3` 东京 MapLibre，不再是早期临时页面。随后把 v3 审计脚本整理成可复用入口，让 map/timetable coverage、bundle integrity、raw train dataset、planner departure visibility 都可以反复跑，而不是靠临时 JSON probing。
- 今天最大的技术工作是 planner-facing departure audit。最早的审计结果非常吓人：有大量 “boardable trip stop 没有被 planner 暴露” 和 “地图上可见的站/线组合没有任何可乘车次”。我们先把问题拆开，确认很多 false positive 来自一个危险规则：只要线路几何靠近某站，就被当成这条线可以在那里上车。这个规则在真实东京网络里会制造大量假换乘、假线路和错误发车列表，所以被移除，改成必须满足 service pattern 和 operator/station 匹配。
- 这一步之后，`visible station/route no-boardable` 从 `105` 降到 `0`，说明 UI 不再显示“有线但永远没车”的假线路。接着继续处理 `unsurfaced boardable trip stops`，发现最大头集中在相鉄直通边界：南北線、副都心線、埼京線・川越線等真实直通服务经过 `羽沢横浜国大`、`西谷`、`海老名`、`湘南台` 一带，但 v3 的物理 alias 还不完整。于是补上了 `相鉄本線`、`相鉄いずみ野線`、`相鉄新横浜線`，并让 planner/audit 知道这些 alias 可以承接对应 JR/Metro/Toei/Tokyu 直通。
- 同时修掉了一个 route identity 细节：Tokyo Metro 采集到的 Odakyu limited express，例如 `メトロホームウェイ`，不应该被站名 signature 误判成 `日比谷線`，而应该归到小田急物理线。这个问题如果留着，会让玩家在 planner 里看到完全不可信的车，所以这次也一起修正。
- 到最终审计时，v3 的 planner warning 已经从早先的 `331` 个 unsurfaced 降到 `9` 个，`no-boardable station/route` 保持 `0`，`forbidden same-operator borrowing` 保持 `0`，核心 v3 unittest suite 仍然 `30` 个全部通过。剩下 `9` 个没有硬压，因为它们已经不是 planner 混线，而是 station identity / 外部线路边界问题：富士急行线的 `赤坂`、水户线方向的 `大和`、大糸线方向的 `有明`，以及 Romancecar 继续到箱根湯本但 v3 尚未 surface Hakone Tozan 物理线。
- 最后写下 `V3_RELEASE_CANDIDATE_NOTES.md`，正式冻结当前 v3 Tokyo MapLibre baseline：明确 v3 继承 v2 玩法，冻结 line -> train -> destination stop 的 planner flow，记录当前数据规模、验证命令、剩余 9 个 warning 的性质，以及 “不要通过放宽规则隐藏 warning” 的 no-regression 要求。也把更大的 station identity、external through-service tails、更大范围网络扩展和进一步性能优化都移动到 v4。
- 到今天结束时，v3 的状态比昨天清晰很多：它不是“完美东京铁路宇宙”，但已经是一个可以被称为 release candidate 的真实东京铁路追逃基线。接下来最自然的工作，不是继续在 v3 上乱加功能，而是从这个稳定点开始规划 v4：先设计更强的 station identity 和外部线路边界模型，再决定更大范围地图和性能架构怎么继续长。
