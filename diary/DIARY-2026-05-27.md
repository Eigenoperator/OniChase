# DIARY - 2026-05-27

今天的主线是把 V5 船港接驳从“还有一堆需要人工判断的灰区”推进到可验证、可玩的状态，同时把机场接驳的旧状态重新核实了一遍。

先处理的是 Codex/VSCode 被大任务拖垮的问题。把 Heavy Data Job Safety 写进了 `AXIOMS.md`：以后涉及全国 bundle、压缩大文件、tile/cache 重建的任务，默认不在 Codex UI 里硬跑，而是给 Scorp 一条安静的终端命令；命令预期输出也要提前说明，尽量只打印 `OK/FAIL` 和少量 summary。这条规则很重要，因为今天一开始的大 bundle audit 已经证明，界面不是跑这种活的地方。

船港这边，先把 remote/small-island 2km 内没有接驳的港口显式落到 `v5_remote_small_island_access_records`，避免 silent gap。随后逐个查官方或准官方来源，把 `remote_access_review_pending` 拆成两类：有真实岛内/港口公交来源的 `official_island_bus_source_found`，以及确认没有固定公共巴士的 `no_scheduled_public_bus`。最后所有 pending 都清空，空的 legacy pending batch 也在收尾复核时删掉了。

接着把 41 个船港接驳候选做成真实 source/runtime 输入。新增并迭代了 `collect_v5_remote_small_island_ship_port_bus_sources.py`，覆盖新岛、西之岛、周防大岛、岡村、壱岐、久米岛、渡嘉敷、桜島、中島、南種子、五島、上五島等一批港口相关接驳。中间经历了几轮 promotion：先发现不少 `skipped_no_trips`，再补齐真正的 stopTimes；最后 remote ship-bus source 收敛到 27 条 route、0 no-trip route，并在 runtime smoke 里验证 27/27 route 都进入 runtime，且都有 weekday trips。

时间模型也定了下来：当前游戏默认 weekday，不做 weekday/weekend UI；weekend/seasonal 数据只作为 source 保存。对应地给 remote route 加了 `serviceProfile`，并让 official-bus augmentation 能识别 weekday/weekend/monday-to-saturday 这类 service-day 字符串。

新岛港是今天比较关键的一次复核。最初 transfer audit 认为它弱接续，但重新渲染并检查新岛村官方ふれあいバス PDF 后，确认 B堤駐車場有 07:55、11:15、16:15 等行，并用 NAVITIME stop timetable 做了交叉验证。补了 11:15 和 16:15 的 source-backed trips，也把低频岛内公交的 transfer window 从 120 分钟调整到 180 分钟。最终 weak transfer queue 清零。

坐标质量也收了尾。先用 Nominatim 做一轮自动 refinement，接受了高置信和距离复核过的点；后来 Scorp 质疑剩下 18 个不能只写“public geocode unavailable”，于是继续查公共 map/stop 页。最后用 NAVITIME、busmap.info、bus-routes.net、Mapion、busmaps.com、OSM/Nominatim 给这 18 个 stop 都补上了公共来源坐标，并新增 `apply_v5_remote_ship_bus_public_coordinate_fixes.py`。promotion 逻辑也修了：已存在 official route 不再只是 skip，而是可以更新同名 stop 的坐标和 source，并只重算这些 stop 的 walking connectors。

船港最终状态是绿的：access priority `remainingActionablePorts: 0`；remote access records 没有 pending；remote ship-bus readiness 没有 no-trip、missing profile、missing port anchor、手工坐标红灯；quality queue 的 coordinate/weak-transfer 都是 0；runtime smoke 是 27/27。

最后转去机场接驳。发现 STATUS 顶部还残留旧的“24 个机场无接驳”描述，但当前 audit 早已变成 75/76 airport-class covered，唯一例外是 KTD/北大東空港，并且它是 documented no-public-bus。补强了 KTD 的 no-bus 来源记录，加入公共岛内交通指南作为交叉来源。随后跑了 `v5_airport_bus_flight_link_audit.js` 的本地 Playwright 测试，HND/NRT/KIX/FUK/CTS/TAK/NKM/KMQ 样本和 targeted KMQ bus-access planning flow 都通过，`failureCount: 0`，console messages 也是 0。

总体上，今天把 V5 船港接驳从“数据还在搜集和解释”推进到了“source、runtime、quality、交互验证都能交代”的阶段。机场接驳也确认不是 coverage 缺口问题，下一步如果继续 V5 公共交通，重点应从机场/船港 coverage 转向更大的 highway/night bus 或更完整的日历模型。
