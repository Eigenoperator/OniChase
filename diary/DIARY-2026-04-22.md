## 2026-04-22

- 今天几乎整天都在把 v3 东京版从“已经能玩”继续往“可以公开反复验证、可以给人看懂、可以持续迭代”推进。主线其实很清楚：一边压实 through-running / physical highlight / replay 这些底层规则，一边把它们变成玩家能看见、也能长期防回归的产品能力。
- 上午先补全了前一天的 diary，然后继续修 v3 计划和列表的可读性。train preview 不再把下一站时间混进文字里，正常长度的行不再无脑滚动，只有超出宽度时才 marquee；`Current Plan` 的 ride leg 也统一加上线路色条，行内只保留真实的 `上車 HH:MM · 下車 HH:MM` 信息，不再出现多余的 `Click to edit...` 提示。
- 随后做了第一次真正意义上的公网双浏览器实玩。用 GitHub Pages 的 `v3.html` 加 Render 的 `onichase-v3-room-server` 连续跑了 10 个公开房间，覆盖桌面/手机视口和多组跨运营换乘。最大的真实问题不是地图，也不是时刻表，而是 online plan submit race：某些多段路线在跨公司、跨等价站换乘后会在 `Current Plan` 里丢段，看上去像玩家没选成功。
- 中午把这个多人核心 bug 正面修掉：room server 增加 monotonic `plan_revision`，客户端也加本地 submit sequence guard，拒绝旧 revision 覆盖新计划，避免慢响应把较新的本地计划回滚。修完后又跑了第二轮 10 个公网房间，之前会掉段的 `東海道線 -> 東横線`、`山手線 -> 京急`、`丸ノ内線 -> 南北線` 等都稳定保留下来。到这一步，v3 公网多人至少在“建房、ready、同步、计划不乱掉”这一层终于比较像样了。
- 下午开始把 battle record / replay 从 debug 输出往“核心资产”推。先写了 `scripts/dev/run_v3_public_battle_records.py`，让它能双浏览器驱动真实公网对局并直接收集 `match_event_log`；然后又写了 `scripts/dev/render_v3_battle_timeline.py`，把对局记录渲染成 Runner 在左、Hunter 在右、中间是时间轴的 SVG 时间线。后面又继续修这些时间线的文字锚点、统一英语 UI 词、去掉内部 route/station id、把私铁前缀和东京 Metro / Toei / Shinkansen 的公开名称映射补齐。
- 再往后把实验强度拉高：battle record 脚本新增 heavy mode，能够生成 10-leg 的长局，并显式检查 `same_node` / `same_train` 抓捕。最终那组公网 heavy regression 跑完之后，battle records、Markdown 报告和长图 timeline 都成体系了：不只是“能打一局”，而是“打一批后还能归档、还能看、还能做 audit”。
- 傍晚之后重心切回 through-running 和地图高光。先把 v3 selected-trip highlight 改成只画这趟车未来的真实物理停站区间，而不是泛泛地把整条 service route 或当前一小段亮起来。接着又修了两个相当关键的边界问题：其一，池袋 `副都心線` 候车列表不能再混入 JR `埼京線・川越線`；其二，东京发 `山手線` 选中后不能因为 fallback 建整张 track graph 把 UI 卡死。最后又进一步把整趟车未来的 physical route choice 调整成按 trip identity、selected route、normalized corridor alias、端点 physical service 等多因素评分，这样 `副都心線 -> 東急東横線 -> みなとみらい21線` 这种全程高光才终于和真实物理运行一致。
- 在这些底层修正稳定之后，今天还做了我觉得特别重要的一件事：把 `AXIOMS.md` 里的 through-running 原则变成可执行测试，而不是只写在文档里。新增的 v3 unittest/browser probe 现在会直接验证东京主要线路分离、新干线和普通线不混、私铁/Metro 边界、selected-train golden highlight，以及 `docs/v3.html` / `ui/v3_maplibre.html` 页面同步。对这个项目来说，这几乎是从“经验修 bug”走向“有生命线的工程化”。
- 晚上继续把 replay / build 这条线补上。先新增 canonical replay record normalizer / validator，把重度公网 battle records 统一整理成 `v3.replay.1` 结构；再把 `docs/v3.html` 确立为 v3 source of truth，`ui/v3_maplibre.html` 只是镜像，并补上同步检查。接着把 replay 直接推进到产品表面：Result / Replay 面板变成可见能力，浏览器内就能构造 canonical replay record、复制 `#replay=...` 分享链接、复制 JSON、从 hash 重新载入 replay，还能直接回答三件事：Runner 怎么走、Hunter 差在哪里、抓捕是怎么发生的。
- 今天最后一段，是开始动“玩家第一次打开看不懂”的 P0。先试过 `Quick Play / Tutorial / Advanced Setup` 三入口，但很快根据反馈把 Quick Play 删掉，只保留 `Tutorial` 和 `Advanced Setup`。Tutorial 也从简单 checklist 扩成更细的教学：line、train、alight、valid plan、LIVE/replay 五步说明，外加普通 ride、through-service、抓捕规则三个 demonstration。然后又顺手把空的 Result / Replay 面板隐藏起来，避免侧栏默认就出现 `No replay yet.` 这类明显打断体验的占位文案。
- 总结今天，感觉 v3 真正完成了一次“从功能堆叠到结构化产品”的跨越。through-running 规则、高光、battle record、timeline、replay、entry 教学、页面 source-of-truth、axiom regression 这些看上去分散的工作，其实都在回答同一个问题：这套东京 chase 玩法能不能既真实、又稳定、还让人看得懂。到今天结束时，我觉得答案已经第一次比较接近“可以了”。
