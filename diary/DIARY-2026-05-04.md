# DIARY 2026-05-04

## 车次高亮与站点高亮

- 今天主要收束 v4 玩法中“选中车次后地图高亮”的逻辑。
- 选中线路时仍然显示线路本身；选中车次时，高亮改为跟随该车次从当前上车点之后还能到达的未来区间，而不是把所属线路全部点亮。
- 对直通车尤其重要：例如新干线 `のぞみ1` 在東京应显示完整的東海道・山陽新幹線未来行程，而不是被拆成很多小段。
- 第一次修正后确认逻辑方向正确，但线上仍可见分段问题；继续定位后发现根因是 geometry slicing 优先取了单条局部 polyline，而没有使用 route graph 中完整的東京 -> 博多路径。
- 最终修正为：当车次自身的 primary route 能覆盖当前到终点的区间时，优先用 primary route；同时 route slicing 在 graph 端点明显更贴近目标时优先使用 graph。
- 为防回归新增 `scripts/tests/v4_selected_train_highlight_audit.js`，全国扫描多 trace 车次，确认 primary route 可以覆盖时不会再被拆碎，并检查几何端点贴近所选起终点。

## 行车中继续规划

- 修复玩家已经在车上时不能继续规划后续路线的问题。
- 现在如果玩家已经计划了一个未来下车站，planning cursor 会从这个未来落点继续展开 1/3 线路选择，而不是一直卡在当前车上的 3/3 下车站选择。
- 如果玩家还没有计划下车站，仍然先显示可下车站列表，保持玩法约束不变。

## Live Timetable 实时刷新

- 修复 live 阶段右侧 timetable/planner 不随游戏时间推进而淘汰已发车车次的问题。
- 出发查询现在使用 `max(plan cursor minute, current game minute)`，所以 06:30 时不会再显示 06:05 已经发走的车。
- 本地浏览器探针确认：東京站 1/3 线路列表在游戏时间 06:30 时最早出发为 `06:30`，推进到 06:31 后最早出发变成 `06:31`。

## Planner 防闪烁

- 在实时刷新基础上继续处理右侧 planner 闪烁问题。
- planner 现在保留稳定外层容器和 page body，不再每次 `renderGame()` 都整块替换 DOM。
- 线路、车次、直挂车、portion、目的地、返回按钮和 empty 状态都带稳定 `data-row-key`。
- 同一页内分钟变化时使用 keyed patch 原地更新行：保留匹配 DOM 节点，只更新文字和属性；新增/移除行做短淡入淡出，并短暂锁定 body 高度减少跳动。
- 跨 1/3、2/3、3/3 翻页时仍然清晰替换页面内容，避免旧页面行和新页面行混在一起。
- click handler 改成覆盖式 `onclick` 绑定，避免 DOM 节点被保留后重复绑定导致一次点击触发多次。
